## pi (2026-11-12)

pi 1.5.2 with `glm-5.3` (z.ai) ran 28 of the 29 trial scenarios once each plus `blocked-sibling` four times and the agent benchmark, from the same prompts as the other agents (`tests/trials/run-pi.sh`, `tests/benchmark/agents/pi.sh`). Slash commands are not available in print mode: the agent reads `.claude/skills/<name>/SKILL.md` as the prompt tells it. On native Windows pi has only a `powershell` shell tool, so the agent starts Git Bash from it. The assertions ran unisolated on that host and the lifecycle results are one run each; see [docs/evals/pi-glm-2026-11-12/summary.md](evals/pi-glm-2026-11-12/summary.md) for what was and was not verified. On 2026-11-13 the same setup reran all 31 scenarios on the revised skill text (pull requests 35 to 38), with reruns of the scenarios each later wording round touched; all passed ([docs/evals/pi-glm-2026-11-13/summary.md](evals/pi-glm-2026-11-13/summary.md)).

## Claude Code on the text of the stuck-worker rules (2026-11-24)

Fresh `claude -p` processes (Claude Code 2.1.331, `claude-sonnet-5-5`, started from the Claude desktop application, Windows 11 with Git Bash, assertions unisolated) ran twelve scenarios once each on `main` at `006d965`: `happy-path`, `status-readonly`, `plan-inline`, `add-lane`, `no-backlog`, `drained-unmerged`, and the six of the stuck-worker rules (`stuck-loop`, `loop-limit`, `time-limit`, `resume-stopped`, `resumed-twice`, `stale-claim`). All 12 passed every assertion. Departures from the text that the assertions do not check: a `time-limit` block whose reason rests on the agent's own measurement, a `Co-Authored-By` line from the host's instruction in the block commit of `resumed-twice`, and a test file committed with mixed line endings. The other 32 scenarios of the Claude Code batch of 2026-11-13 were not rerun on the current text or harness, so nothing is shown for them here. It is one run per scenario, so no count is a rate; the loop guard's count was not reached; and the session logs that the times and tool calls come from were not archived. See [docs/evals/claude-code-2026-11-25/summary.md](evals/claude-code-2026-11-25/summary.md). Codex on the current text is in the next section.

## Codex on the text of the stuck-worker rules (2026-11-24)

Fresh `codex exec` sessions (codex-cli 0.167.0 in the Docker image `todo-codex-linux:0.167.0`, `gpt-6.1-terra`, started from Windows 11 with Git Bash, assertions unisolated) ran twelve scenarios once each on `main` at `006d965`: `happy-path`, `status-readonly`, `plan-inline`, `add-lane`, `no-backlog`, `drained-unmerged`, and the six of the stuck-worker rules (`stuck-loop`, `loop-limit`, `time-limit`, `resume-stopped`, `resumed-twice`, `stale-claim`). 10 passed every assertion and 2 failed. The two failures are `time-limit` (10 of 12 assertions) and `stuck-loop` (9 of 11): each agent stopped after one red run with no code written, the node still `[/]` and no block commit. The summary reads `stuck-loop` as a gap in the skill text and the agent's choice in about equal parts, and `time-limit` mainly as the agent's choice; one run each, with no reasoning in the event stream, so neither is firm. `loop-limit` blocked at the third attempt, and the worker that is gone and the stale claim followed the text in 3 of 3 runs. Departures from the text that the assertions do not check: among them a node commit that says `Reviewed: subagent` where the stream shows none (`drained-unmerged`), a resume decision taken on `git log -5` with the own command of the rule in the same call as the resume commit (`resume-stopped`), and the push alternative left out of the printed merge commands against the prompt (`drained-unmerged`). What Codex did not run on the current text: the other 32 scenarios, of which 25 ran on 2026-11-14 on older text (22 passed and 3 failed one assertion each there) and 7 did not run then (Java, multi-session, lanes, shared remote). The limits: Linux containers only, one run per scenario so no count is a rate, the version of Codex inferred from the image, the client's own instructions and the model's reasoning not in the evidence, and the loop guard's count not reached. See [docs/evals/codex-linux-2026-11-25/summary.md](evals/codex-linux-2026-11-25/summary.md).

## Unsupported or unverified

- Codex: Linux lifecycle results are provisional (the boundary audit is partial: the profile allows general OS reads and the verifier can read its controller); on native Windows the trial assertions run in the elevated Codex sandbox by default (FIX-041, `docs/evals/fix-041.md`): login, evaluator and evidence sentinels are denied and the controller is read-only, but like the Linux profile it permits general OS reads, and the lifecycle batch rerun with it on 2026-11-08 scored 2 PASS, 0 FAIL and 6 INFRA_ERROR, each with its cause: Codex's unelevated Windows sandbox still blocks the `.git` writes lifecycle needs, and Maven could not read its host cache there (TASK-045, `docs/evals/codex-windows-2026-11-08/summary.md`). Parallel Codex lanes were recorded on Linux (TASK-044). The existing-project trial that needed a backlog-commit workaround was rerun without it and passed (TASK-043).
- Codex on the revised skill text (2026-11-14): 27 of the 34 trial scenarios in Linux containers, one fresh `codex exec` session each: 24 passed and 3 failed one assertion each, which TASK-124 tracks; the other seven (Java, multi-session, lanes, shared remote) were not run, and the verifier was not isolated (`docs/evals/codex-linux-2026-11-14/summary.md`).
- Codex on the current text (2026-11-24): 12 of the 44 trial scenarios in Linux containers, one fresh `codex exec` session each: 10 passed and 2 failed (`time-limit`, `stuck-loop`). The other 32 were not rerun on it: 25 ran on 2026-11-14 on older text and 7 did not run then; the verifier was not isolated (`docs/evals/codex-linux-2026-11-25/summary.md`).
- Concurrent lanes on either agent: `tests/trials/lane-evidence.sh` reports `unverified` for worktree events alone and `concurrent` only with controller-owned worker-activity records (FIX-036). Codex: `run-codex-lanes.sh` starts one fresh Codex process per lane and records each worker's tool activity from its event stream; its `multi-module` run was `concurrent` and passed (`docs/evals/lanes-codex-2026-11-08/summary.md`, TASK-044). Claude Code: no recorded run has such records; the earlier `lanes` runs judged overlap from the session's Agent calls and commit times (`docs/evals/claude-code-2026-11-07/summary.md`).
- Other agents (Cursor, Gemini CLI and so on) can read the skills as Markdown, but nothing has been run there.
