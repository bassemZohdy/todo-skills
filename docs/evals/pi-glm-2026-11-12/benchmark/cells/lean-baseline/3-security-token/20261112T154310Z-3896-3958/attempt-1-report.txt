## Summary

**What changed**
- `auth/tokens.py` — implemented `verify(token, secret, now)`: splits the token into exactly three `.`-separated parts, rejects an empty user, parses the expiry as an integer, recomputes the HMAC-SHA256 over `"<user>.<expires_at>"` and compares it to the token's signature with `hmac.compare_digest` (constant time), then enforces `now < expires_at`. Valid tokens return the user name; expired, wrong-secret, tampered, and malformed tokens (wrong part count, non-integer expiry like `abc`/`1e5`, empty user, non-string inputs) all raise `InvalidToken` — a final guard converts any stray exception so no other exception can escape.
- `tests/test_tokens.py` — 19 `verify` tests: happy path, expiry boundary (`now == expires_at - 1` accepted; `==` and `>` rejected, including negative expiry), wrong secret, tampered user/expiry/signature, truncated signature, malformed shapes, and type-abuse inputs.
- `TASKS.md` — plan with all four subtasks marked done; one commit per subtask (`37b1964`, `f4b4887`, `974c865`, `7c853a1`), each landing after its tests failed first and then passed.

**Interpretation decisions (no blocking questions; the spec was complete on boundaries, exception type, and constant-time compare)**
- "Not three parts" is read literally: `split(".")` must yield exactly 3 parts, so a user name containing a dot (which `sign` would render as 4 parts) is rejected as malformed.
- "Integer expiry" follows `sign`'s own `int()` coercion: any `int()`-parseable string is an integer; anything else (`1e5`, `abc`, `2026-01-01` splits into extra parts) is malformed. Non-canonical forms like `" 100"` parse but then fail the signature check, since the HMAC is recomputed over the normalized payload.
- `verify` also raises `InvalidToken` for non-string `token`/`secret` values (a defensive extension of "never another exception" beyond the enumerated cases).

**Left open**: nothing for this scenario. If you later want dotted user names supported, that requires changing the token format (e.g., `rsplit(".", 2)` plus updating `sign`), which would invalidate existing tokens.
