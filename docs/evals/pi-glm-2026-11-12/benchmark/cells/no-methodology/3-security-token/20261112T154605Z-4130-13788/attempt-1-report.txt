## Summary

**`auth/tokens.py`** — implemented `verify(token, secret, now)`:
1. **Structure**: splits the token into exactly three parts (`user`, `expires_at`, `signature`); anything else — including non-strings — raises `InvalidToken`.
2. **User**: empty user → `InvalidToken`.
3. **Expiry parsing**: non-integer or non-canonical expiry (e.g. `+100`, `010`) → `InvalidToken`; the canonical check ensures the value round-trips what `sign` produces.
4. **Signature**: recomputes the HMAC-SHA256 hex digest over `"<user>.<expires_at>"` and compares with `hmac.compare_digest` (constant time) — this also covers tokens signed with a different secret.
5. **Freshness**: rejects when `now >= expires_at` (expired at the exact boundary too).
6. Returns the `user` name on success.

**`tests/test_tokens.py`** — kept the existing `SignTest` and added acceptance tests (valid token returns the user, boundary just before expiry, constant-time comparison used via a `compare_digest` spy) plus one rejection test per required case: exact expiry, past expiry, wrong secret, tampered signature/user/expiry, two parts, four parts, non-integer expiry, empty expiry, non-canonical integer expiry, empty user (built via `sign` so only the user is invalid), and non-string token. Every rejection asserts specifically `InvalidToken`.
